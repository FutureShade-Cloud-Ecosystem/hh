@hardscapehouse/design-system harness

Static page, no build and no scripts: every kit in its ready state and its five designed states (empty, loading, offline, conflict, error), at the two walkthrough widths. Rendered by Node from the kit render functions themselves, each cell into its own declarative shadow root, so every kit is painted under its own stylesheet. The committed pages are exactly this page in its four builds: index.html (dark, base brand, the double-click default) beside index-light.html, index-hh-pro.html and index-light-hh-pro.html, each opening from the file itself, with the per-kit sheets the build writes under harness/sheets/ travelling with them (a page without that folder renders unstyled); node --import ./src/_ts-js-loader.mjs harness/serve.mjs serves the same variants live: add ?theme=light for the light half and ?brand=hh-pro for the standalone shell's brand override. Each width frame is its walkthrough width capped to the window, so the page never scrolls sideways; in a window narrower than a walkthrough width the capped frames show at the window width and look the same, which is what their labels say.
