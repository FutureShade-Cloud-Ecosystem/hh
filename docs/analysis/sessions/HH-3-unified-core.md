# HH-3: the unified core

Goal: make `core/` a conforming Go monolith that carries every HardscapeOS module, the HH Pro domain rules that belong server-side, org and tenant scoping, JWKS authentication, role gating from the contract, sync endpoints per declared scope, and a standing lane that keeps tracking the in-flight HardscapeOS delivery until cutover.
Preconditions: HH-2 (skeleton, manifest, OpenAPI, ADR drafts written from D1, D2 and D3 in `analysis/DECISIONS.md`); no platform dependency: this session runs on a preview database with the same shape and on JWKS tokens signed by test-generated keys, until S0 (Managed Postgres, the `dibbits` org database) and S2 (Appwrite identity, real JWKS tokens) exist; both are preconditions of HH-5, not of this session.
Position relative to the ERP cutover session: upstream. The core runs beside HardscapeOS against a restored copy of its database in this session; it becomes a co-writer of the live org database only in HH-5.
Harness: claude for HH-3.3, HH-3.4 and HH-3.5 (identity, gating, sync: security-critical); mixed elsewhere. Integrator and verifier on Claude.

Lanes (parallel unless marked):
- HH-3.1 Baseline and the additive schema
  Scope: carry `hardscapeos_dibbits/backend/migrations/0001` through the last file as the baseline of `core/db/migrations`, unedited. Then additive migrations only: `org_id` on every org-owned table and `tenant_id` on every tenant-scoped table per `analysis/domain-map.md` section 5; `seq` per declared scope with a server-side allocator; `deleted_at` tombstones on synced tables; the HH Pro entities the ERP lacks (`plan`, `plan_line`, `customer_quote`, `quote_acceptance`, `attachment`) in the shapes `domain-map.md` section 5.4 gives, the `legacy_contractor_id` alias column on the unified order for the mapping period (D6), and the D13 to D18 columns (`analysis/DECISIONS.md`): `lead_time_days` as a product attribute with no stored availability (D13, availability is computed); `dealer_quote.valid_until` at document level and a per-line `price_snapshot` with `resolved_at`, stock holds as separate objects with their own expiry (D14); `product_id` as the live reference on every line plus the frozen priced fields at document freeze (D15); `is_special_order`, `special_order_description` and an optional `supplier_ref`, with a one-time migration that parses the legacy synthetic sku prefix into the boolean and keeps the original sku in the snapshot (D16); the contractor stop projection's fields (D17); and the org surcharge configuration, off by default, credit-only, with the jurisdiction and its cap recorded (D18), with both candidate shapes carried where a conflict stayed open; `citext` kept as is, per the extensions ADR that adds it to the allowlist (HH-2.4). Nothing destructive: HardscapeOS must keep running against this schema unchanged.
  Touches: `hh/core/db/migrations/`; `hh/core/db/README.md` with the additive-only rule and the ledger of ported ERP migrations.
  Acceptance: the migrations apply from zero and on top of a restored HardscapeOS dump; the ERP's own integration suite (`hardscapeos_dibbits/backend/internal/gate`, run against this database) still passes, which proves the additions are invisible to the old application; `GATE-5a` (migrations clean) and `GATE-5b` (journals balance) pass; the special-order migration parses every synthetic sku in the seed and the restored dump with none left unparsed (D16); no table stores availability (D13).
  Prompt: "Bring the HardscapeOS migration set into `core/db/migrations` verbatim as the baseline, then write additive migrations for `org_id`, `tenant_id`, per-scope `seq`, `deleted_at`, and the entities in `docs/analysis/domain-map.md` section 5 that the ERP lacks. Every new column is nullable or defaulted so the running ERP is unaffected. Prove it by running the ERP's integration suite against the migrated database. No em or en dashes; no dates."

- HH-3.2 Module carry and the single binary

Leave `demo` behind. Break the 4,311-line composition root into `wire<Module>` functions as `docs/design/MODULE_FRAMEWORK.md` section 2 asked, without changing any wiring decision.

  Acceptance: `go build ./... && go vet ./...` clean; the untagged unit suite (312 files) passes unchanged; the outbox drains from the `worker` role and not from `serve`; a test asserts `serve` starts no scheduler.
  Prompt: "Move the HardscapeOS Go modules into `hh/core/internal` without changing behaviour, collapse the four binaries into `cmd/core` with `serve`, `worker` and `migrate` roles, move the scheduler and the outbox dispatcher into `worker`, delete the unused `events.Bus`, and split `main.go` into per-module wire functions. Keep every adapter type and every guard decision exactly as it is. The existing unit suite must pass unchanged. No em or en dashes; no dates."

Carry the ERP's approval rail and the driver session ceiling as policy over claim lifetime.

  Acceptance: the RBAC-403 sweep (`TestSurface_GuardedWritesRejectUnderTier`), the anonymous sweeps (HS-2) and the order lifecycle route test pass against JWKS-signed test tokens; a test proves a valid token with a wrong `X-Org` never reaches a repository; a test proves a tenant token cannot read another tenant's rows on any tenant route.
  Prompt: "Replace HardscapeOS's two HS256 JWT paths with JWKS verification against the platform, add `X-Org` and tenant scoping as middleware per `context/FUTURESHADE-CONTEXT.md` section 4.4, and carry the 13 staff roles plus the ERP portal's contractor role set (canonical per `docs/analysis/DECISIONS.md` D3, HH Pro roles mapped once) as app roles keyed by platform user id, with driver as a role plus a profile row. - HH-3.5 Sync endpoints per scope
  Scope: `GET /sync/{scope}?since={seq}` returning ordered rows and tombstones, `POST /sync/{scope}` replaying an outbox in order with client-generated ids as idempotency keys, server-assigned `seq`, per-entity conflict policy from the manifest (`server_wins`, `last_write_wins_by_field`, `manual` returning server state and a review marker), for every scope `manifest.yaml` declares. Start with the two full-mode scopes (yard-pick: `pick_tasks`, `shortages`, `receiving`, `inventory_lookup`, `weights`, `attachments`; drive-run: `runs`, `stops`, `pod`, `attachments`), then the read-cache-plus-outbox scopes.
  Touches: `hh/core/internal/sync` (new), the `seq` allocator from HH-3.1, `hh/core/api/openapi.yaml` (already authored in HH-2.3).
  Acceptance: contract tests per scope; `GATE-7` (idempotent replay) generalised to every scope; a property test that two replays of one outbox produce one server state; a test that `manual` never overwrites and always returns the server row.
  Prompt: "Implement the sync protocol from `context/FUTURESHADE-CONTEXT.md` section 4.5 for every scope in `hh/manifest.yaml`, full-mode scopes first. Server assigns `seq`; deletes are tombstones; conflicts follow the manifest's per-entity policy; a client id is an idempotency key. Generalise the ERP's idempotent-replay gate test to every scope. No em or en dashes; no dates."

- HH-3.6 HH Pro domain rules move server-side
  Scope: the stage machine and its guard sentences (`hh_pro_dibbits/src/core/domain/stage.ts`), price expiry re-blocking a placeable plan, the customer-quote freeze, token rotation on revise, the signed acceptance artifact, and `quotePayment` (fee shown equals fee charged) become core behaviour on the `plan`, `customer_quote` and `payment` routes, in Go, with the refusal sentence returned verbatim in the error envelope so the board drop and the agent tool result read the same words. The D13 to D18 rules (`analysis/DECISIONS.md`) land here too: `availability` as a computed read model with `source` in {attribute, incoming_supply, transfer}, where incoming supply or a transfer estimate overrides the attribute for that quantity (D13); expiry re-blocks the plan at document level, from `dealer_quote.valid_until`, and D1's estimate label expires with the document (D14); before freeze the live reference renders and after freeze the snapshot renders, the reference serving navigation only (D15); a special-order line is the boolean, never a sku prefix (D16); the contractor's view of a stop is an ETA window, the stop status (planned, en route, delivered, exception), the driver's first name and the proof of delivery, never the route, the sequence or other stops (D17); the card surcharge is off by default and, when enabled for an org, credit-only, capped by the jurisdiction's rule, with the jurisdiction recorded, and fee shown equals fee charged byte for byte (D18).
  Touches: `hh/core/internal/plan` (new), `hh/core/internal/customerquote` (new), `hh/core/internal/payments`.
  Acceptance: the stage tests in `hh_pro_dibbits/src/core/domain/__tests__/stage.test.ts` and the review-regression cases that concern these rules (`src/core/__tests__/review-regressions.test.ts`) are ported one for one and pass against the Go implementation; the sentence catalogue (singular and plural forms) is asserted byte for byte; enabling a surcharge requires a recorded jurisdiction and its cap, and the action refuses without both (D18); a surcharge is never applied to a non-credit tender and never exceeds the recorded cap (D18); the contractor stop view serialises none of route, sequence or other stops (D17); an expired `dealer_quote` re-blocks the plan and a fresh one unblocks it (D14).
  Prompt: "Port HH Pro's stage machine, price-expiry guard, customer-quote lifecycle and payment quote rule from `hh_pro_dibbits/src/core/domain` and `src/core/actions` into Go modules in `core`, preserving every contractor-facing refusal sentence verbatim and porting the TypeScript tests one for one, and implement D13 to D18 from `docs/analysis/DECISIONS.md` (computed availability, document-level expiry, freeze semantics, the special-order boolean, the contractor stop view, the jurisdiction-recorded surcharge). The pricing behaviour follows D1 in `docs/analysis/DECISIONS.md` (contract price final; else base, then a replacing quantity break; promotions a separate never-stacking level), not either repository's current resolver. No em or en dashes; no dates."
